# Changelog

All notable changes to this project are documented here. Format: Keep a Changelog. Versioning: SemVer.

## [Unreleased]

### Fixed
- History durability: an unreadable `history.json` (permissions, I/O) is now an error instead of an empty history that the next save would overwrite; only a missing file is empty and only a corrupt one is set aside. Reads, changes and writes run under an exclusive `flock` on `history.lock`, so concurrent runs keep every record. The Cleaner stamps each trashed item's identity right when it moves it (the save no longer does), so a file the user trashes later with the same name is never purged. `spare undo --dry-run` previews without restoring. `purge` returns its failures (printed to stderr, non-zero exit) and history I/O errors are told apart from an unknown id (exit 74). Only `<volume root>/.Trashes/<current uid>/<item>` counts as a volume Trash.
- Cleaner hardening: emptying the Trash now runs first, so it can never destroy an item the same run just moved there; a path listed twice is processed once; paths with `.` or `..` components are refused; project idleness is measured from the outermost project root; tools run with empty stdin and time limits (5 s lookup, 300 s command, injectable), a timeout ends the tool and reports the item as failed; the login shell lookup takes the last path line and can be injected, so tests never start a real shell.
- Homebrew cache is now deleted directly (`Library/Caches/Homebrew`, regenerable downloads) instead of running `brew cleanup --prune=all`, which also removes old versions of installed formulas.
- In-use detection no longer skips processes started through PATH (`node`, `cargo`, `npm`): their real path comes from `proc_pidpath`. Process listing has a 5 s timeout (`lsof -b -w`), a failed `ps` marks items that need the check as `unknown` instead of free, and `scriptName` skips interpreter flags.
- Project leftovers idleness: measured at the whole repository root (a `.git` directory or file above the artifact, inside the project root), so a monorepo package is idle only if the entire repo is. Creation dates and the artifact folder's own modification date also count as activity, covering unzipped or restored projects followed by an install.
- Safety guard hardening: user files refuse folders that contain protected or critical ones (`~/Library`, `~/Documents`, `~/Desktop`); `children` rules now enforce extensions and minimum age; project artifacts require their manifest and never enter `.git`; generic rules refuse paths owned by specific rules; hard links are tracked by device and inode.

### Added
- Cleanup guards: "Clean what's safe" does nothing (and the Overview button is off) while a cleanup runs, a scan cannot start while a confirmation is open, a dropped confirmation says nothing was cleaned, quitting during a cleanup waits for the item in progress and saves the record, a record that could not be saved is shown with a warning (never an older one), `--snapshot` refuses `SPARE_HOME` equal to the real home, and item counts use proper plurals (`Localizable.stringsdict`, en and pt-BR).
- Cleanup flow in the app: category cards with the Safe or Review badge, a Review screen per category (checkboxes, safe items ticked, items in use or not verified shown with the reason and never selectable, Show in Finder), a confirmation that says what is deleted for good and what goes to the Trash (and warns when the Trash itself is emptied), live progress with Stop (the item in progress finishes, the rest is skipped), and a result with free space before and after, Undo and "Free it now". The Cleaner runs off the main actor and nothing runs before the confirmation. Progress events are matched to items by path (they arrive in execution order). "Clean what's safe" is on the Overview and the Cleanup screen. The History screen lists past cleanups with a detail view and Undo; an unreadable `history.json` shows an error instead of an empty list. `SPARE_TRASH_DIR` (or `SPARE_HOME` alone, which uses `<home>/.Trash`) keeps a fake-home run away from the real Trash. `--snapshot` now also draws the cleanup cards, review, confirmation, progress, result and history.
- App shell: menu bar item (mini Spare ring and free GB, a warning triangle below the alert threshold), a dark panel with Disk, Memory (biggest users every 5 s, light `ps` listing) and Today's recommendation cards, and a 1000 x 660 main window with the Overview screen. "Analyze" runs the real scan off the main actor with per category progress and a working Stop; project discovery now honors cancellation and reports the folders it reads. Items in use show "In use by <app>", items whose check failed show "Not verified", and neither is selectable. The Dock icon exists only while the window is open. Settings (`settings.json`), the last scan (`last-scan.json`) and the recommendation logic live in the core; the CLI honors the saved settings. The design system (`Ink`, `Txt`, `Backdrop`, buttons, `Tile`, `Badge`, `Card`, `Checkbox`, the Spare Ring) moved from the prototype to `Sources/SpareApp/Design/`.
- `--snapshot <dir>` (needs `SPARE_HOME` on a fake home) draws the panel and the Overview states to PNG in-process, and `scripts/snapshot.sh` builds a fake home and runs it (output in `docs/img/`). `--show <section>` opens the window on a section.
- Large files: `spare large [PATH] [--min-mb N] [--limit N] [--json]` lists the biggest files under a folder (default: home). Read-only walk that never follows symlinks, skips packages, `.git`, the Trash, system folders and protected places (keys, Mail, Messages, iCloud Drive), keeps only the N biggest in a small heap and stops on cancellation. `spare large --trash FILE... [--yes] [--dry-run]` moves chosen regular files to the Trash through the same guards as the Cleaner (`canTrashUserFile`), stamps each with its identity and records the cleanup so `spare undo` works. Previews without `--yes`.
- Memory: `spare memory` shows used memory, pressure and the apps and tools using the most (helpers grouped under their app). Numbers are approximate: public APIs only (`host_statistics64`, `sysctl`), and resident memory counts shared pages in every process. `spare status` now includes memory. The core has a safe `ProcessTerminator` (by pid, SIGTERM by default, injectable quitter) that refuses other users, pid 1, Spare itself, the terminal and shell ancestors of the current process and system paths (checked against the live path); there is no CLI command for it. The Memory listing is a light `ps`-only call. Tests never signal a real user process (injected recorder or a child started by the test).
- Cleanup history, undo and purge, plus `spare clean`, `undo`, `purge`, `history` and `rules`. History lives in `Application Support/Spare/history.json` (last 100 cleanups, folder `0700`, file `0600`; a corrupt file is renamed, never deleted). Items sent to the Trash are stamped with their device and inode: undo and purge only touch the exact item Spare moved, still directly inside the Trash (a later item with the same name, a symlink or a forged path is left alone). Undo never overwrites, not even a dangling symlink; the item stays in the Trash and the result says why. Purge ("free now") deletes only Spare's own Trash items, marks them `purged`, and never empties the Trash. `clean` and `purge` only preview without `--yes` and always preview with `--dry-run`. `SPARE_TRASH_DIR` and `scripts/qa-fake-home.sh` allow an end to end run on a fake home.
- Cleaner with four actions: delete, move to the Trash (undoable), official tool command (once per rule) and empty the Trash. Right before each item it re-runs the safety guard, honors the scan's in-use flag (including `unknown`), checks running processes (one listing per run; a failed listing skips every item that needs the check) and, for project leftovers, re-measures idleness at the repository root. Anything that changed is skipped with a reason, never deleted. The scanner and the guard share one catalog and one clock (`environment.now`).
- `canTrashUserFile` refuses files inside `Library/Mail`, `Library/Messages` and `Library/Mobile Documents`.
- In-use detection: the scan lists the user's running processes once (`ps` plus the working directory from `lsof`) and sets `ScanItem.inUseBy` for items an app, tool or MCP server is using. An npx package counts as in use when a process names its folder in the command line or runs with it as working directory (symlink spellings such as `/var` and `/private/var` match). Official-command rules are never blocked, and a shell parked in a project folder does not block that project's artifacts.
- Approved visual prototype (`Prototype/run.sh`, mock data, no disk access) and design system in `.interface-design/system.md`: dark gradient, the Spare Ring, sidebar with colored tiles. Product principles recorded in the PRD: safe and visibly so, polished, light, intuitive.
- Idle project leftovers (`node_modules`, `.venv`, `.next`, `target`) in scans: only projects untouched for 30 days, manifest required next to the artifact, `.git` ignored, symlinks never followed. `live` environments use the conventional project roots (`Projetos`, `Projects`, `dev`, `Developer`, `code`).
- Walking skeleton: disk monitor, `spare status`, menu bar app showing free space, local gates and a minimal CI (secret scan and `.env` check on PRs, full gate on manual dispatch). CLI errors go to stderr.
- Rule catalog, safety guard and read-only scan (`spare scan`). Sizes never follow symlinks and count hard links once.
